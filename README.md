# Fenrir

CPU-focused password cracker targeting memory-hard hash algorithms: Argon2 (primary), bcrypt, and scrypt.

Named after the wolf of Norse mythology — bound by the gods because nothing else could contain it.

---

## Why CPU, not GPU

Most password crackers (Hashcat, John the Ripper) are GPU-optimized for fast hashes like MD5, NTLM, and SHA. For those, a GPU wins by an enormous margin.

Memory-hard algorithms are different. Argon2, bcrypt, and scrypt are designed to require large amounts of RAM per attempt. This collapses the GPU advantage:

- A GPU has thousands of cores but limited per-core cache and memory bandwidth
- Argon2 at m=65536 requires 64MB of RAM per hash attempt
- An M4 Pro with 24GB RAM can sustain ~375 parallel Argon2 attempts
- A GPU with 24GB VRAM has the same ceiling but slower per-core memory access

Fenrir uses Rust and rayon to maximize CPU throughput on these specific algorithms. On an M4 Pro, it is genuinely competitive with GPU crackers for high-memory Argon2.

## Running

Once built, the binary is at `./target/release/fenrir`. You need two things to run it: a hash to crack and a wordlist.

**Step 1 — Get a hash to crack**

If you are testing on your own system, generate one first:

```bash
pip install argon2-cffi
python3 -c "from argon2 import PasswordHasher; print(PasswordHasher().hash('wolf123'))"
```

This prints something like:

```
$argon2id$v=19$m=65536,t=3,p=4$c2FsdHNhbHRzYWx0$hashhashhashhash
```

Copy that entire string. That is your hash.

**Step 2 — Get a wordlist**

On macOS, rockyou.txt is not pre-installed. The fastest way to get it:

```bash
brew install hashcat
# After install, find it with:
find /usr/local /opt/homebrew -name "rockyou.txt" 2>/dev/null
```

Or download it directly:

```bash
curl -L -o rockyou.txt.tar.gz https://github.com/danielmiessler/SecLists/raw/master/Passwords/Leaked-Databases/rockyou.txt.tar.gz
tar xzf rockyou.txt.tar.gz
```

For a quick test without rockyou, make a small wordlist:

```bash
echo -e "password\nwolf\nwolf123\nletmein\n123456" > test.txt
```

**Step 3 — Run it**

```bash
./target/release/fenrir \
  -H '$argon2id$v=19$m=65536,t=3,p=4$c2FsdA$yourhashhere' \
  -w test.txt \
  --stats
```

If the password is in the wordlist (or generated by the rule engine from a word in it), you will see:

```
  PASSWORD FOUND

  plaintext:   wolf123
  hash:        $argon2id$v=19$m=65536,t=3,p=4...

  candidates:  140
  elapsed:     2.31s
  throughput:  60/sec
```

**Step 4 — Optional: install globally**

```bash
cp ./target/release/fenrir /usr/local/bin/
```

Then you can run `fenrir` from anywhere without the path prefix.

## Usage

```
fenrir [OPTIONS]

Options:
  -H, --hash <HASH>            The hash string to crack
  -w, --wordlist <PATH>        Path to wordlist file (one candidate per line)
  -r, --rules <RULES>          Mutation rule set: none, basic, leet, full [default: basic]
  -t, --threads <N>            Thread count [default: all logical cores]
  -a, --algorithm <ALG>        Override algorithm detection: argon2, bcrypt, scrypt
  -s, --stats                  Show live candidates/sec counter
  -h, --help                   Print help
```

## Examples

```bash
# Crack an Argon2id hash with basic rules
fenrir \
  -H '$argon2id$v=19$m=65536,t=3,p=4$c2FsdA$hashhere' \
  -w /usr/share/wordlists/rockyou.txt

# Use the full rule set (more mutations, more time)
fenrir \
  -H '$argon2id$v=19$m=65536,t=3,p=4$c2FsdA$hashhere' \
  -w wordlist.txt \
  --rules full

# Crack a bcrypt hash, limit to 12 threads (M4 Pro performance cores)
fenrir \
  -H '$2b$12$saltsaltsaltsalthashhashhashhashhashhashhashhas' \
  -w rockyou.txt \
  --threads 12

# Show live throughput stats
fenrir -H '$argon2id$...' -w wordlist.txt --stats

# Use a small targeted wordlist with no mutations
fenrir -H '$argon2id$...' -w targets.txt --rules none
```

## Rule sets

Rules mutate each wordlist candidate to generate additional candidates without storing them on disk. This is called a rule-based attack.

| Rule set | Mutations per word | Description |
|---|---|---|
| none | 1 | Words used exactly as-is |
| basic | ~20 | Case variants + common numeric and symbol suffixes |
| leet | ~5 | Character substitutions (a to 4, e to 3, i to 1, o to 0, s to 5) |
| full | ~80 | All of the above combined |

Examples of what `basic` generates from the word "wolf":

```
wolf
Wolf
WOLF
wOLF
wolf1
wolf2
wolf123
wolf2024
Wolf123
Wolf2024
wolf!
wolf@
...
```

## Architecture

```
src/
├── main.rs       CLI parsing, algorithm detection, thread pool setup
├── wordlist.rs   Buffered wordlist streaming via crossbeam channel
├── rules.rs      Mutation engine (case, numeric suffixes, leet, combined)
├── hashes.rs     Hash verification backends (Argon2, bcrypt, scrypt)
├── cracker.rs    Parallel crack loop using rayon par_iter + find_any
└── output.rs     Result and stats reporting
```

### Concurrency model

Fenrir reads wordlist lines from a background I/O thread through a bounded crossbeam channel. For each word, the rule engine generates a Vec of mutations. That Vec is handed to rayon's `par_iter().find_any()`, which distributes the mutations across all threads in the pool and returns the first match found, cancelling remaining work immediately.

This design:
- Decouples disk I/O from CPU work (reader runs ahead, buffers 10,000 lines)
- Parallelizes at the mutation level — right granularity for slow hashes
- Exits immediately on a match without finishing the current batch

### Release profile

The Cargo.toml release profile uses:

```toml
opt-level = 3      # maximum LLVM optimization
codegen-units = 1  # whole-crate optimization (slower compile, faster binary)
lto = true         # link-time optimization across all crates
```

On Apple Silicon, LLVM will emit ARM NEON instructions automatically. You do not need to set target-cpu manually for M4 — rustc targets the native architecture when building natively.

## MITRE ATT&CK

Fenrir maps to T1110.002 (Brute Force: Password Cracking). Offline password cracking requires prior access to a credential database or hash dump. Common sources:

- Database dump from a compromised web application
- SAM/NTDS.dit from a Windows domain controller
- /etc/shadow from a Linux host
- Password manager database file
